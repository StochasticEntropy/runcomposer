# The connector surface, name by name

Generated by `python ci/sdk_names.py` from the modules themselves — do not
edit by hand; `tests/test_sdk_names.py` fails when this file and the code
disagree. Every name exported by the connector surface is listed with the
first sentence of its own documentation (a constant: the comment above its
definition). [connectors.md](connectors.md) is the guide that explains how
they fit together; the stability promise of its §1 covers each name with the
meaning given here and in its docstring.

## `runcomposer.sdk.robot`

| Name | Meaning |
|---|---|
| `attribute_roots` | Which suite root each item is executed from — checked, also for a single root. |
| `clean_output` | Rewrite one ``output.xml`` without the keyword data ``settings`` selects — ``{remove_keywords: [...], flatten_keywords: [...]}``, Robot's own ``--removekeywords`` / ``--flattenkeywords`` selectors — through Robot's result model, atomically: the cleaned file is written beside the output and then replaces it. |
| `collect_verdicts` | Parse every output of a finished shard through ``ctx.parse`` and label each verdict with the attempt its output is. |
| `deliver_shard` | Deliver one finished shard under its name and record what it left to read: ``log.html``, ``report.html`` and ``output.xml`` as artifacts of the shard, and the shard's directory itself (so that what a log refers to — screenshots — is servable). |
| `ExactSelection` | Pre-run modifier: keep exactly the tests whose longname is in ``ids`` — no pattern matching, so an id is never read as a glob — optionally tag every kept test, and drop the suites left empty. |
| `Execution` | One Robot execution inside a shard: these tests, from this root. |
| `GroupMerger` | One merged result per shard group and one for the whole dispatch, recorded as artifacts of the group and of the run — each merged in a spawned process (:func:`spawn_merge`), so the dispatching process never runs Robot itself. |
| `LiveStatusListener` | Robot listener (API v3): ``RUNNING`` when a test starts, its status when it ends — written to a ``LiveChannel``, so it works in a worker process and with any RunStore. |
| `merge_outputs` | Combine several ``output.xml`` into one ``output.xml`` (and ``log.html`` / ``report.html``) in ``out_dir``: later outputs merged over earlier ones (``merge=True`` — executions of one root: chunks, reruns), or side by side under one top-level suite (``merge=False`` — executions of different roots). |
| `MergeNoiseRemover` | Pre-rebot modifier: when outputs of *disjoint* executions are merged, every test and suite of a later output is stamped "added from merged output" in place of — or in front of — its own message. |
| `MergePayload` | Everything a merge process needs — the arguments of :func:`merge_outputs`. |
| `MergeResult` | How a merge ended: the merged ``output.xml`` (and ``log.html`` / ``report.html`` beside it when asked for), or why there is none. |
| `NameTopSuites` | Pre-rebot modifier for outputs combined side by side (``merge=False``): gives the top-level suites, in the order the outputs were given, the names in ``names`` — so that the same suite executed on two partitions reads as ``eu`` and ``us`` instead of twice ``Tests``. |
| `read_shard_result` | The hand-back a worker left in its output directory, ``None`` when there is none (the worker was killed before it could write one). |
| `RemoteLiveStatusListener` | :class:`LiveStatusListener` for an execution runcomposer did not start itself — a CI job, a remote agent: it pushes to the API, authorized by the ingest token of its dispatch, instead of writing to a local channel. |
| `RESULT_FILE` | What a worker writes into its output directory when it is done (or dies trying): the hand-back the supervising process reads. |
| `robot_version` | The installed Robot Framework's version, ``None`` when it is not installed (``pip install 'runcomposer[robot]'``). |
| `root_mismatches` | Every item of ``item_ids`` that belongs to none of ``suite_roots``, each as a sentence naming the item and the root — empty when all belong. |
| `run_merge` | Merge-process entry: :func:`merge_outputs` with the payload's arguments, and what happened written to :data:`_MERGE_RESULT_FILE` in ``payload.out_dir``. |
| `run_shard` | Worker entry: execute one shard with real Robot Framework and write what happened to :data:`RESULT_FILE` in ``payload.out_dir``. |
| `ShardOutcome` | How one payload ended under :func:`supervise`. |
| `ShardOutput` | One ``output.xml`` a worker produced: which attempt it is, how many tests were selected for it and how many of them existed under ``root``. |
| `ShardPayload` | Everything one worker process needs to execute one shard. |
| `ShardResult` | What a worker handed back. |
| `spawn_merge` | :func:`run_merge` in a spawned process, waited for: the calling process imports nothing of Robot Framework and never touches its process-global logger, so a server can merge while it serves — and several merges can run at once. |
| `STOP_FILE` | Left in a worker's ``out_dir`` when it is asked to stop. |
| `supervise` | Run ``payloads`` on spawned worker processes, at most ``max_workers`` at once, and hand each back as it finishes — ``supervise_workers`` of the SDK with :func:`run_shard` as the worker. |
| `VARIABLE_NAME_PATTERN` | The shape of a Robot variable name a payload may set (a regular expression, matched whole): letters, digits, ``_``, spaces, ``.`` and ``-``, beginning with a letter, a digit or ``_`` — no ``${…}``, and in particular no ``:`` (Robot splits ``--variable NAME:value`` at the first one, so ``BASE_URL:https`` would set ``${BASE_URL}``) and no ``=``. |
| `variable_name_problem` | Why ``name`` cannot be set as a Robot variable by a payload — a sentence naming it — or ``None`` when it can (:data:`VARIABLE_NAME_PATTERN`). |
